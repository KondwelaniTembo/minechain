# Live anchoring run on Sepolia, 9 November 2026

The first end-to-end run of the anchoring worker against the deployed MineChain contract.
One demo consignment was taken through registration, handoff and purchase, and each step
was anchored on Ethereum Sepolia by the backend's recorder wallet.

The on-chain values below were recorded by the developer from Etherscan. Nothing in this
document is estimated; where a figure is derived from others, the arithmetic is shown.

## What was run

On the developer's Windows laptop, against the development database, with the chain
settings in `backend/.env` (primary RPC: PublicNode; fallback RPC: 1RPC):

1. `npm run demo:journey`, which created three fresh demo users with in-memory device keys,
   then signed and synced a registration, a handoff and a purchase for a new QR code
   through the real sync pipeline. All three steps were stored as `passed` and `pending`.
2. The anchoring script, `anchor:once`, run several times over the day. On PowerShell,
   `node scripts/anchor-once.js --until-idle` was used, because
   `npm run anchor:once -- --until-idle` lost its flag (see Observations).

Each run did the startup checks (preflight) first, then reconciled anything in flight and
sent at most one step: the worker's one-transaction-in-flight rule.

The final run, `node scripts/anchor-once.js --until-idle`, took the journey to the end:

| Tick | Outcome |
|---|---|
| 1 | Confirmed the handoff and sent the purchase |
| 2 | Waiting: the purchase was not yet deep enough |
| 3 | `idle [confirmed 1 …]`: confirmed the purchase, then found nothing left to send |

It printed `confirmed cc3ec3e6-a232-4deb-83f6-9904e21ab151:
https://sepolia.etherscan.io/tx/0xcf794b211b6949809884422ddd8d54b579cef2b966f0cc27c659ff5d888f2e8f`
and ended with "Idle: nothing is waiting to be anchored." **All three steps ended
`confirmed` in the database.**

## Gas: why registration costs about six handoffs

The contract was designed with the plan's estimate of about 95,000 gas for a registration.
Sepolia charged 352,951. The code does not explain the difference; the network's gas
schedule does.

**What the write functions do** (`contracts/contracts/MineChain.sol`). All three check the
role (one storage read), check that no input is zero, read the current stage, write one
`Consignment` struct of three storage slots (stage, weight and timestamp packed into slot 0;
`actorRef`; `dataHash`) and emit one event. There are no arrays, counters or other mappings.
The only structural difference is that a registration writes three **new** slots (zero to
non-zero), while a handoff or purchase updates three existing ones.

**Measured both ways:**

| Function | Local, Osaka rules (`npx hardhat test --gas-stats`) | Sepolia, Glamsterdam (this run) |
|---|---|---|
| `registerConsignment` | 96,645 | 352,951 |
| `recordHandoff` | 45,449 (median; range 45,449–45,515) | 59,299 |
| `recordPurchase` | 45,336 | 59,182 |

The local run had 37 tests passing, and reported a deployment cost of 1,204,173 gas and
5,201 bytes of bytecode.

**The cause, confirmed:** the Glamsterdam upgrade activated on Sepolia on 2026-10-06 at
13:53:36 UTC. It includes:

- **EIP-8037, state creation gas.** A zero-to-non-zero SSTORE now also costs state gas for
  the state it creates: 64 state bytes × 1,530 (the cost per state byte) = 97,920 per new
  slot.
- **EIP-8038, state access repricing**, which raises the cost of reading and writing
  existing state.

**The arithmetic matches the code:**

- On Sepolia: 352,951 − 3 × 97,920 = **59,191**, against a handoff of 59,299 and a purchase
  of 59,182. Take away the three new slots, and a registration costs the same as the other
  two writes.
- Locally (Osaka): creating a slot costs 20,000 where updating one costs 2,900, a premium of
  17,100. 96,645 − 3 × 17,100 = **45,345**, against a handoff of 45,449 and a purchase of
  45,336. The same pattern under the old rules.
- The handoff and purchase are each about 13,800–13,900 gas dearer on Sepolia than locally
  (59,299 − 45,449; 59,182 − 45,336), which is where EIP-8038's state-access repricing
  shows.

**Caveats:**

- EIP-8037 is still in Review, so the cost per state byte (1,530) may change.
- Glamsterdam is not on Ethereum mainnet yet. Costs on mainnet, or on a layer 2, would
  follow that network's schedule.
- At this run's gas prices (53 to 1,317 wei) all three steps together cost less than a
  billionth of an ETH. The gas figures matter for the wallet balance checks, not for money.

**What changed in the code as a result:** preflight's per-transaction ceiling,
`MAX_GAS_PER_STEP` in `backend/src/chain/preflight.js`, went from 120,000 (sized from the
old estimate) to 450,000, and the test fake's gas figures now use these measurements.
Sending itself was never affected: it checks the balance against the node's real estimate.

## Observations

- **Preflight passed on every run** (chain id, contract code, role).
- **1RPC refused `eth_sendRawTransaction`**, classified as `RPC_UNAVAILABLE`, while
  PublicNode accepted the same signed transaction. In practice 1RPC works as a read-only
  fallback: it helps with reads when the primary is down, but cannot send.
- **PowerShell dropped the `--`** in `npm run anchor:once -- --until-idle` (npm's PowerShell
  shim, `npm.ps1`), so the script never saw `--until-idle`.
  `node scripts/anchor-once.js --until-idle` worked.
- **About 82% of each gas limit was used**, as expected from the 1.2 headroom.

[decisions.md](decisions.md) (9 Nov 2026).
